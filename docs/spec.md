# ข้อกำหนด OCR Playground

สถานะ: ร่างสำหรับ issue tracker จากขอบเขตที่ตกลงกัน รายละเอียด API เป็นข้อเสนอและยังไม่มี implementation

## Problem Statement

ผู้ใช้ต้องการทดลองถอดข้อความจากเอกสารตัวพิมพ์ภาษาไทยและอังกฤษ และตรวจแก้ผลเทียบกับต้นฉบับได้ โดยมีโปรเจกต์ portfolio ที่สาธิตการทำงานตั้งแต่อัปโหลดจนดาวน์โหลดผล

## Solution

สร้าง backend ที่รัน OpenThai OCR Text บน CPU และ frontend ที่รับภาพหรือ PDF หนึ่งไฟล์ ประมวลผลทุกหน้า แสดงภาพคู่กับผล และให้แก้ไข คัดลอก หรือดาวน์โหลดโดยไม่เก็บข้อมูลถาวร ใช้งานบนเครื่องตัวเองก่อน

## User Stories

1. ในฐานะผู้ใช้ ฉันต้องการอัปโหลด JPG เพื่อถอดข้อความจากภาพ
2. ในฐานะผู้ใช้ ฉันต้องการอัปโหลด PNG เพื่อถอดข้อความจากภาพ
3. ในฐานะผู้ใช้ ฉันต้องการอัปโหลด PDF หลายหน้าเพื่อถอดข้อความทุกหน้า
4. ในฐานะผู้ใช้ ฉันต้องการเห็นชนิดและขีดจำกัดไฟล์ที่รองรับก่อนอัปโหลด
5. ในฐานะผู้ใช้ ฉันต้องการทราบเมื่อไฟล์เสีย ไม่รองรับ มีรหัสผ่าน หรือเกินขีดจำกัด เพื่อเลือกไฟล์ใหม่
6. ในฐานะผู้ใช้ ฉันต้องการเห็นสถานะรอและประมวลผล เพื่อทราบว่างานยังดำเนินอยู่
7. ในฐานะผู้ใช้ ฉันต้องการเห็นจำนวนหน้าที่ประมวลผลแล้ว เพื่อประเมินความคืบหน้า
8. ในฐานะผู้ใช้ ฉันต้องการดูต้นฉบับคู่กับผล เพื่อเทียบและตรวจข้อความ
9. ในฐานะผู้ใช้ ฉันต้องการเลือกดูแต่ละหน้า เพื่อค้นหาและแก้ไขข้อความ
10. ในฐานะผู้ใช้ ฉันต้องการแก้ไขข้อความทั้งหน้า เพื่อแก้ข้อผิดพลาด OCR
11. ในฐานะผู้ใช้ ฉันต้องการให้ข้อความที่แก้ยังอยู่เมื่อสลับหน้า เพื่อไม่ต้องแก้ซ้ำ
12. ในฐานะผู้ใช้ ฉันต้องการคืนค่าผล OCR เดิมเฉพาะหน้า พร้อมยืนยันก่อน เพื่อย้อนการแก้ไขโดยไม่ทับข้อมูลโดยไม่ตั้งใจ
13. ในฐานะผู้ใช้ ฉันต้องการเพิ่มข้อความในหน้าที่ OCR ไม่พบข้อความ เพื่อให้ผลสมบูรณ์ขึ้น
14. ในฐานะผู้ใช้ ฉันต้องการเห็นว่าหน้าใดล้มเหลวและดูหน้าที่สำเร็จต่อได้ เพื่อใช้ผลบางส่วน
15. ในฐานะผู้ใช้ ฉันต้องการคัดลอกข้อความ เพื่อใช้ในงานอื่น
16. ในฐานะผู้ใช้ ฉันต้องการดาวน์โหลด TXT รวมหน้าพร้อมเลขหน้า เพื่อเก็บข้อความตามลำดับ
17. ในฐานะนักพัฒนา ฉันต้องการดาวน์โหลด JSON ที่แยกข้อความแก้ไขจาก OCR เดิม เพื่อประมวลผลต่อโดยไม่สับสน
18. ในฐานะนักพัฒนา ฉันต้องการข้อมูลตำแหน่งและความมั่นใจของ OCR เดิม เพื่อใช้วิเคราะห์ผล
19. ในฐานะผู้ใช้ ฉันต้องการคำเตือนและข้อมูลหน้าที่ล้มเหลวเมื่อดาวน์โหลดผลไม่ครบ เพื่อไม่เข้าใจผิดว่าผลสมบูรณ์
20. ในฐานะผู้ใช้ ฉันต้องการใช้งานโดยไม่สมัครบัญชี เพื่อทดลองได้ทันที
21. ในฐานะผู้ใช้ ฉันต้องการลบข้อมูลชั่วคราวเมื่อจบงานและให้ข้อมูลที่เหลือหมดอายุ เพื่อจำกัดการเก็บเอกสาร
22. ในฐานะผู้ใช้ ฉันยอมเริ่มใหม่หลังรีเฟรชหรือปิดหน้า เพื่อใช้ระบบแบบไม่เก็บประวัติถาวร

## Implementation Decisions

- ใช้ OpenThai OCR Text บน CPU โดยตรวจสอบรูปแบบผลจริงก่อนยืนยันการแปลงข้อมูล
- รับไฟล์ครั้งละหนึ่งไฟล์ สร้างงานแบบ asynchronous และตรวจสถานะด้วย polling
- ให้สถานะงานและหน้ารองรับผลสำเร็จบางส่วน หน้าที่ไม่มีข้อความเป็นหน้าสำเร็จ
- API ให้ข้อมูลสถานะ รายการหน้า ผล OCR เดิม และภาพรายหน้า รวมทั้งลบงานชั่วคราว รายละเอียดเป็นสัญญาฉบับร่างในเอกสาร API
- Frontend เก็บข้อความแก้ในหน่วยความจำแยกจากผลเดิม และสร้างไฟล์ดาวน์โหลดหลังดึงผลทุกหน้าที่สำเร็จ
- กรอบและค่าความมั่นใจอ้างอิง OCR เดิม พิกัดต้องตรงกับภาพที่แสดง และต้องตรวจช่วงความมั่นใจจริงของโมเดล
- ลบข้อมูลเมื่อผู้ใช้จบงานอย่างชัดเจน และใช้เวลาหมดอายุลบข้อมูลตกค้าง ขนาดไฟล์ จำนวนหน้า และระยะเวลาต้องกำหนดหลังทดลอง

## Testing Decisions

- ทดสอบพฤติกรรมที่สังเกตได้ผ่าน HTTP API เป็นจุดเชื่อมหลัก ครอบคลุมไฟล์ที่รองรับ สถานะ หน้าว่าง ผลบางส่วน ข้อผิดพลาด และการลบหรือหมดอายุ
- ทดสอบการเชื่อมโมเดลจริงด้วยชุดภาพและ PDF ตัวอย่าง เพื่อยืนยันการอ่าน การแปลงพิกัด และการทำงานบน CPU โดยไม่ใช้คะแนนคุณภาพที่ยังไม่ได้วัดเป็นเกณฑ์
- ตรวจ flow ของ frontend ตั้งแต่อัปโหลดจนแก้ คืนค่า และดาวน์โหลด รวมถึงผลบางส่วน โดยยืนยันพฤติกรรมที่ผู้ใช้มองเห็น
- ยังไม่มีโค้ดหรือชุดทดสอบเดิมใน repository ให้ใช้เป็นตัวอย่าง สามารถใช้โมเดลจำลองใน API tests เพื่อควบคุมกรณีผิดพลาด และแยกทดสอบโมเดลจริง

## Out of Scope

บัญชีผู้ใช้ ประวัติถาวร การเปิดใช้งานสาธารณะ การส่งหลายไฟล์ เลือกหน้า ยกเลิกงาน ลองใหม่เฉพาะหน้า การใส่รหัส PDF การแสดงกรอบและความมั่นใจบนหน้าจอ และ OCR Markdown สำหรับตารางหรือลายมือ

## Further Notes

ระบบนี้เป็น portfolio สำหรับเครื่องตัวเอง ยังต้องทดลองคุณภาพกับเอกสารจริงและกำหนดขีดจำกัด อายุข้อมูล และทรัพยากรที่เหมาะสมก่อนสรุปค่าตั้งต้น
