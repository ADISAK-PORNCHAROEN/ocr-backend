# Security model

## ขอบเขตและหลักฐาน

สถานะ: แบบจำลองจากแผนที่ตกลง ยังไม่มี implementation หรือผล security scan ทบทวน 2026-11-22

แหล่งอ้างอิงคือ [ขอบเขตโปรเจกต์](project-scope.md), [ข้อกำหนด](spec.md), [สถาปัตยกรรม](architecture.md), [โครงสร้างที่เสนอ](folder-structure.md), [คู่มือ frontend](frontend-guide.md) และ [สัญญา API ฉบับร่าง](frontend-api.md) ข้อกำหนดในเอกสารเหล่านี้ยังไม่มีโค้ดหรือการทดสอบพิสูจน์การบังคับใช้

ระบบเป้าหมายเป็น portfolio บนเครื่องเดียว เริ่มสาธิตผ่าน loopback ไม่มีบัญชีและไม่เปิดใช้งานสาธารณะ การเผยแพร่หรือเพิ่มผู้ใช้หลายคนเปลี่ยนสมมติฐานนี้และต้องทบทวนแบบจำลองก่อน

## ข้อมูลและขอบเขตความเชื่อถือ

| ข้อมูลหรือผู้เกี่ยวข้อง | เจ้าของตามแผน | ขอบเขต |
| --- | --- | --- |
| เอกสารต้นฉบับ ภาพหน้า และผล OCR เดิม | API process จัดการสถานะและ artifacts ชั่วคราว | ข้อมูลผู้ใช้อาจมีเนื้อหาส่วนตัว ยังไม่มีข้อกำหนด classification หรือ logging ที่ยืนยัน |
| ข้อความที่แก้และไฟล์ดาวน์โหลด | Frontend เก็บในหน่วยความจำและสร้างดาวน์โหลด | ไม่ส่งข้อความแก้กลับไปเก็บถาวรตามขอบเขตปัจจุบัน |
| ไฟล์ JPG, PNG และ PDF ที่ส่งเข้า | ข้อมูลภายนอกที่ต้องตรวจ | ผ่าน HTTP ไปยังตัวอ่านไฟล์และ native OCR runtime |
| OCR worker | รับข้อมูลหน้าและส่งผลกลับ | ไม่เป็นผู้เขียนสถานะงานโดยตรง API process เป็นผู้รับผลและเปลี่ยนสถานะ |

เส้นทางตามแผน: `Frontend → HTTP API → บริการงาน → ตัวอ่านเอกสารและ OCR worker → ผลรายหน้า` API จัดการข้อมูลชั่วคราวและการลบ Frontend อ่านภาพและผลเพื่อแสดง แก้ และดาวน์โหลด

ไม่มีระบบตัวตนหรือการแยก tenant ที่ตกลงไว้ และยังไม่ได้กำหนดกลไกควบคุมผู้ที่เข้าถึง `jobId` ขอบเขต local demo ไม่ใช่หลักฐานว่ามี authorization แล้ว

## Invariants ที่ตกลงและวิธีพิสูจน์

Enforcement ของทุกรายการยังไม่พัฒนา ตารางนี้เป็นข้อกำหนดสำหรับตรวจ implementation ในอนาคต

| ข้อกำหนด | เจ้าของตามแผนและหลักฐาน | กรณีทดสอบที่ต้องพิสูจน์ |
| --- | --- | --- |
| ตรวจชนิดและเนื้อหาไฟล์ ขนาด จำนวนหน้า และปฏิเสธ PDF ติดรหัสผ่านหรือเปิดไม่ได้ | ตัวอ่านเอกสารและ HTTP boundary ตามขอบเขตและ API ฉบับร่าง | ชื่อหรือนามสกุลไม่ตรงเนื้อหา ไฟล์เสีย ไฟล์เกินขีดจำกัด PDF มีรหัสผ่าน |
| จำกัดขนาดไฟล์ จำนวนหน้า พิกเซลภาพ จำนวนงาน และข้อมูลในคิว | บริการงานและตัวอ่านเอกสารตามสถาปัตยกรรม ตัวเลขยังไม่กำหนด | ทดสอบที่ขอบค่าและเกินค่า รวมกรณีคิวเต็มหลังยืนยัน error contract |
| API process เป็นผู้เขียนสถานะและที่เก็บ artifacts เพียงรายเดียว | สถาปัตยกรรมกำหนด API หนึ่ง process และ worker ส่งผลเท่านั้น | ทำงานหลายหน้าแล้วอ่านสถานะระหว่างทาง โดยไม่มีตัวนับขัดกับสถานะหน้า |
| ลบหรือหมดอายุแล้วเข้าถึงงานไม่ได้ทันที ผล worker ที่มาช้าสร้างงานกลับไม่ได้ | บริการงานทำเครื่องหมายลบก่อน และลบไฟล์เมื่อ worker เลิกใช้ ตามสถาปัตยกรรม | ลบหรือหมดอายุระหว่าง inference แล้วส่งผล worker กลับ ตรวจว่าอ่านงานและภาพไม่ได้และไฟล์ถูกลบเมื่อปลอดภัย |
| ลบต้นฉบับ ภาพหน้า และผล OCR โดยไม่มีประวัติถาวร | ขอบเขต API และสถาปัตยกรรมกำหนดการลบชัดเจน หมดอายุ และล้างไฟล์ตกค้างเมื่อเริ่มระบบ | จบงาน ปิดหน้าโดยไม่ส่ง delete และหยุด process กะทันหันแล้วเริ่มใหม่ ตรวจพื้นที่ชั่วคราวที่ทดสอบเป็นเจ้าของ |
| ข้อความแก้แยกจากผล OCR เดิม | คู่มือ frontend และ API ฉบับร่าง | แก้ข้อความแล้ว export ตรวจว่า OCR เดิม พิกัด และความมั่นใจไม่ถูกแทนด้วยข้อความแก้ |

## เส้นทางการใช้ผิดและข้อจำกัด

| อินพุตและเส้นทาง | ผลกระทบที่ต้องตรวจ | สิ่งที่ยังไม่พิสูจน์ |
| --- | --- | --- |
| ไฟล์ภายนอก → ตัวอ่าน PDF หรือภาพ → native runtime | ไฟล์เสียหรือใช้ CPU และ RAM เกินทรัพยากร | ยังไม่มี parser ที่เลือก รุ่น dependency ขีดจำกัด หรือผลทดสอบจริง |
| ลบหรือหมดอายุ → worker คืนผลช้า → บันทึกผล | ข้อมูลที่ลบกลับมาเข้าถึงได้ หรือไฟล์ตกค้าง | ยังไม่มี lifecycle implementation หรือ race tests |
| `jobId` และเลขหน้าจาก HTTP → อ่านภาพ ผล หรือลบงาน | เข้าถึงงานผิดรายการหรือ path นอกพื้นที่ชั่วคราว | การสร้าง ID การ map path และการตรวจสิทธิ์ยังไม่กำหนด ต้องตรวจจากโค้ดจริง |
| เนื้อหา OCR → frontend และข้อความ error | เนื้อหาจากไฟล์ถูกแสดงอย่างไม่ปลอดภัย หรือเปิดเผย path ภายใน | ยังไม่มี rendering, error handling หรือ logging policy ให้ตรวจ |

รายการนี้เป็นสถานการณ์สำหรับทบทวน ไม่ใช่ช่องโหว่ที่ยืนยันแล้ว ยังไม่ได้กำหนด CORS, origin policy, timeout, log redaction หรือการป้องกันนอกขอบเขต loopback เจ้าของโปรเจกต์ต้องยืนยันตาม deployment จริงก่อนเปิดการเข้าถึงเพิ่ม

## การทบทวนและหลักฐาน

การเปลี่ยนโค้ด dependency executable configuration หรือ CI ใช้ workflow ของ `.agents/skills/security-review/SKILL.md` เมื่อ setup ติดตั้ง package นั้นครบแล้ว ตรวจ diff และ boundary ที่กระทบ การสแกนทั้ง repository เป็นงานแยกจากการตั้งค่า workflow

บันทึกขอบเขต revision หรือ patch แหล่งโค้ด เส้นทางอินพุตสู่ผลกระทบ เงื่อนไข และผลทดสอบในรายงานงานนั้น แยก candidate, confirmed, fixed และ verified ใช้ข้อมูลและพื้นที่ชั่วคราวที่แยกจากเอกสารจริง ดู [การทดสอบ](TESTING.md) และ [นโยบายที่ยังต้องกำหนด](../SECURITY.md)
