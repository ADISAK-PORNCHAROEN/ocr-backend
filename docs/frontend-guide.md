# คู่มือออกแบบ frontend

สถานะ: UX specification สำหรับ frontend repository แยก; frontend implementation และ local integration อยู่ใน branch `develop` ดู [สัญญา API](frontend-api.md) และ [ขอบเขตโปรเจกต์](project-scope.md)

## ลำดับการใช้งาน

1. ผู้ใช้เลือก JPG, PNG หรือ PDF หนึ่งไฟล์ หน้าจอแจ้งชนิดและขีดจำกัดที่รองรับเมื่อกำหนดแล้ว
2. ส่งไฟล์สร้างงาน แสดงสถานะรอและความคืบหน้าระหว่างประมวลผล
3. เมื่อประมวลผลเสร็จ แสดงภาพต้นฉบับคู่กับข้อความและตัวเลือกหน้า แยกสถานะสำเร็จ ไม่พบข้อความ และล้มเหลว
4. ให้ผู้ใช้แก้ไขข้อความของแต่ละหน้า คัดลอก และคืนค่าข้อความ OCR เดิมของหน้าปัจจุบันโดยยืนยันก่อน
5. ดาวน์โหลด TXT หรือ JSON ได้ หากบางหน้าล้มเหลวให้แจ้งว่าผลไม่ครบก่อนดาวน์โหลด
6. เมื่อผู้ใช้เริ่มใหม่หรือจบงาน ให้ส่งคำขอลบข้อมูลชั่วคราว

## การจัดการข้อมูลในหน้าเว็บ

เก็บข้อความแก้ไขแยกตามงานและเลขหน้าในหน่วยความจำของ frontend ใช้ข้อความ OCR เดิมเป็นค่าเริ่มต้นและเก็บต้นฉบับไว้สำหรับปุ่มคืนค่า การเปลี่ยนหน้าไม่ทิ้งข้อความที่แก้ แต่การรีเฟรชหรือปิดหน้าเริ่มใหม่

หน้าที่ OCR ไม่พบข้อความยังเปิดช่องว่างให้แก้ไขได้ หน้าที่ล้มเหลวแสดงข้อผิดพลาดและไม่แสดงว่าเป็นหน้าว่างที่สำเร็จ หน้าเวอร์ชันแรกไม่แสดงกรอบหรือค่าความมั่นใจ

## ดาวน์โหลด

ก่อนสร้างไฟล์ ให้ดึงผล OCR ของทุกหน้าที่สำเร็จ แม้ผู้ใช้ยังไม่เปิดดูหน้านั้น TXT ใช้ข้อความที่แก้แล้วเมื่อมี รวมหน้าไว้ในไฟล์เดียวและคั่นด้วยเลขหน้า ระบุหน้าที่ล้มเหลวด้วย

JSON เก็บข้อความแก้ไขแยกจากข้อความ OCR เดิม ตำแหน่งและค่าความมั่นใจอ้างถึงผล OCR เดิมเท่านั้น JSON ระบุสถานะและข้อผิดพลาดของหน้าที่ล้มเหลวด้วย ดูตัวอย่างใน [สัญญา API](frontend-api.md#รูปแบบ-json-สำหรับดาวน์โหลด)

## สถานะที่ต้องออกแบบ

- รอประมวลผล กำลังประมวลผล และความคืบหน้ารายหน้า
- สำเร็จทั้งหมด สำเร็จบางส่วน หรืองานล้มเหลว
- ไม่พบข้อความ หน้าล้มเหลว ไฟล์ไม่รองรับ ไฟล์เสีย PDF ติดรหัสผ่าน และไฟล์เกินขีดจำกัด
- งานหมดอายุหรือถูกลบ ให้ผู้ใช้เริ่มใหม่

การปิดแท็บอาจส่งคำขอลบไม่สำเร็จ backend จึงต้องลบข้อมูลหมดอายุด้วยตัวเอง
