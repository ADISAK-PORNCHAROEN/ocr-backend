# ร่าง tickets สำหรับ OCR Playground

สถานะ: รอตรวจสอบขอบเขตและ dependencies ก่อนเผยแพร่เป็น GitHub issues รายการนี้แบ่งเป็นพฤติกรรมที่ตรวจสอบได้ โดย frontend เป็นโปรเจกต์แยกและแต่ละ ticket ระบุผลที่ผู้ใช้หรือผู้เรียก API ตรวจได้

1. **ถอดข้อความภาพหนึ่งหน้าผ่าน API** — Blocked by: ไม่มี ตรวจสอบการรันโมเดลจริงบน CPU และส่งภาพเพื่อรับผล OCR พร้อมภาพต้นฉบับและข้อมูลรายบรรทัด
2. **ติดตามงาน OCR และความคืบหน้ารายหน้า** — Blocked by: 1 สร้างงานเบื้องหลังและตรวจสถานะตั้งแต่รอจนสิ้นสุดผ่าน API
3. **ถอด PDF หลายหน้าและรักษาผลบางส่วน** — Blocked by: 2 ประมวลผลทุกหน้า แสดงหน้าว่างและหน้าที่ล้มเหลวแยกกัน พร้อมใช้ผลหน้าที่สำเร็จ
4. **ตรวจสอบไฟล์และขีดจำกัด** — Blocked by: 3 แจ้งไฟล์เสีย ชนิดผิด PDF ติดรหัสผ่าน และไฟล์หรือจำนวนหน้าเกินขีดจำกัดที่วัดแล้ว
5. **ลบงานและหมดอายุข้อมูลชั่วคราว** — Blocked by: 2 จบงานแล้วลบไฟล์และผล พร้อมลบข้อมูลตกค้างเมื่อหมดอายุ
6. **ตรวจและแก้ผล OCR ใน frontend** — Blocked by: 3 แสดงต้นฉบับคู่ข้อความ เลือกหน้า แก้และคัดลอกข้อความ จำระหว่างสลับหน้า และคืนค่าหน้าปัจจุบันเมื่อยืนยัน
7. **ดาวน์โหลด TXT และ JSON รวมผลทุกหน้า** — Blocked by: 6 ดาวน์โหลดข้อความที่แก้และผล OCR เดิม แสดงคำเตือนและระบุหน้าล้มเหลวเมื่อผลไม่ครบ
8. **เชื่อม flow อัปโหลด สถานะ และเริ่มใหม่** — Blocked by: 4, 5, 6, 7 เชื่อมหน้าจอกับ API ครบตั้งแต่อัปโหลด แสดงความคืบหน้า แจ้งข้อผิดพลาด จนลบงานเมื่อเริ่มใหม่

แต่ละ ticket ที่เผยแพร่ต้องมี acceptance criteria และระบุ blockers เป็น GitHub issue references
